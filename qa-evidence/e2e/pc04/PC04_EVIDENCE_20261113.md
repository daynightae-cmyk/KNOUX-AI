## What the service really does

`PrivacyRepository` reads **only this package** through public Android APIs: declared
permissions (PackageManager), the media grant and persisted SAF trees (PermissionState),
`android:allowBackup` and the debuggable flag (ApplicationInfo), cleartext policy
(NetworkSecurityPolicy), notification state (NotificationManagerCompat), and the live
`FLAG_SECURE` bit of the KNOUX window. Three tables (Room v4) store scans, findings and
actions append-only. The only privacy setting KNOUX owns is screenshot protection; it is
applied to the real window, re-read from `window.attributes.flags`, and recorded as
`VERIFIED` only on a match. Android-owned screens are recorded as `OS_SCREEN_OPENED`,
never as a fix. Other apps' permissions are always `UNMEASURABLE` / `NOT_POSSIBLE`.

  flag clear and **100** with it set. The score is 100 minus fixed penalties over the four
  scored checks (`privacy_scans.scoredCount = 4`); informational and unmeasurable rows never
  score.
- Toggling screenshot protection applied the real `WindowManager.LayoutParams.FLAG_SECURE`
  bit (asserted from `activity.window.attributes.flags`), the platform accepted it, the audit
  journal shows `SETTING_APPLIED/REQUESTED → SETTING_VERIFIED/VERIFIED`, and the verified
  flag triggered a new measured pass whose stored score rose by exactly the LOW penalty (+8).
- Turning it off again restored the original preference, and the post-test settings file
  holds `privacy_secure_window = false` (protobuf `12 02 08 00`).
- Persisted history: 12 privacy scans, 144 findings, append-only; every one of the 12 checks
  appears exactly once per pass. `OTHER_APP_PRIVACY` is stored as `UNMEASURABLE` with
  `NOT_POSSIBLE` in every pass.
- Room `3 → 4` migration proved on device: a real v3 database with checkpointed
  `scan_sessions`/`residue_scans`/`residue_decisions` rows migrates, keeps its rows, creates
  the three privacy tables empty, reports `user_version=4` and `PRAGMA integrity_check=ok`.
  The installed app's own database now reports the same (`db/post-test/`).

## Defects found and fixed during this task

1. **Aggregate audit rows were dropped.** `PrivacyController.observeAudit()` mapped
   `checkId="ALL"` (MEASURED/REVIEWED) through the `PrivacyCheck` enum, so those actions
   silently disappeared from the action history. The storage test caught it; the mapper now
   accepts an aggregate row with `check = null` and the UI labels it `all checks`.
2. **Test helper read a container's text.** The UI test asked a card container for
   `SemanticsProperties.Text` instead of asserting the visible disclosure; it now asserts
   the real "does not expose other apps" text is on screen.
3. **Second navigation loop still assumed a design fixture.** `everyRemainingPrimaryAction...`
   walked all five tool entries through `detail-scroll-*`, which PC04 correctly removed for
   Privacy. The loop now verifies the measured privacy screen and skips the preview dialog,
   exactly as PC02/PC03 did for their measured screens.
